# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| >=5.3.6   | :white_check_mark: |
| <5.3.6   | :x:                |

## How to Report a Vulnerability

In the case that you, the user of the Dynamic Learning Model (DLM) open-source framework, suspect any security vulnerability, 
**please DO NOT open a public GitHub issue for security bugs.** Report the vulnerabilities privately by emailing **vignesh.tho2006@gmail.com** or 
by navigating to the security tab of this repository and clicking "Report a vulnerability"

To help us resolve the issue quickly, please share:

* A description of the **vulnerability** and its potential **impact**
* Step-by-step instructions to **reproduce** the issue
* A minimal **Proof of Concept** (PoC) script or **payload** if applicable

## What to Expect

* **Acknowledgment**: You will receive a manual confirmation within 48 hours of submission
* **Updates**: Our team will provide progress updates every **3 to 5 business** days while we try to fix the issue
* **Accepted Reports**: If verified, we will collaborate with you privately to develop a patch.
  You will be credited in our release notes (unless you prefer to remain anonymous).
* **Declined Reports**: If we determine the issue is not a security vulnerability, we will provide a detailed explanation
  of our reasoning and close the report.

## Disclosure Policy

We follow coordinated vulnerability disclosure. We ask that you give us up to 90 days to patch the issue before making any details public.
